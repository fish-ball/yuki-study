# 确保 / 修订知识点教程

## 何时使用

- 精讲 / 预习某个 `knowledge_id` 之前
- 学生要「学一学」「看教程」「讲义」
- 出题或批改后需要补充、纠正讲解材料
- **新学了关联知识点**（先修、同模块相邻点、同卷考查点）之后
- 学生在练习中暴露出新的易错点
- **学生对章节内容追问、澄清、问为什么、要反例**（回答中的可复用信息按重要性入库）

## 硬原则（动态修正）

1. 教程是**可演进文档**，不是一次性成品。
2. 已有正确内容：**保留并在原基础上补充**，禁止无故整篇覆盖删除。
3. 发现错误、过时表述、或学生新错因：必须**落盘修订**（升 `version`，写 `updated_at`），禁止只口头改口。
4. 关联内容加入后：必须**整合**进相关教程（互链 + 必要对照），不能只新建孤立讲义。
5. **追问即教材**：澄清对话里出现的高/中重要性知识点，默认写入教程，无需学生额外授权。

## 追问 / 澄清 → 按重要性入库

学生围绕某课、某题、某 `knowledge_id` 追问时，先完整回答；再判断本次回答中的信息是否入库：

| 重要性 | 典型内容 | 动作 |
|--------|----------|------|
| 高 | 纠错、定义边界、判别标准、常考结论、与已学点对照 | **必须**写入对应教程；冲突则纠正 |
| 中 | 好例子、口诀、步骤、符号规范 | **应当**写入（例题演示 / 核心概念 / 易错点） |
| 低 | 鼓励语、重复原文、一次性算式细节 | **不写** |

落盘位置（按内容选一处，可多处）：

- 定义/边界 → `## 核心概念`
- 例子 → `## 例题演示`
- 易混/纠错 → `## 易错点`
- 与其他点关系 → `## 关联知识点` + `related_ids`

流程：

1. 归因到具体 `knowledge_id`（必要时多个，分别修订）。
2. 若教程不存在 → 先新建再补入。
3. 修订 Markdown：`version += 1`，`revision_note` 写清「追问补充：…」。
4. 答复末尾用一句注明：已写入 `knowledge_id` 的某某小节（管理台「学习」可刷新查看）。

禁止：只在对话里讲清楚却不改教程文件；把低价值闲聊整段贴进教程。

## 步骤

1. 读取 `knowledge/<subject>/tree.yaml`，确认 `knowledge_id`，记下 `name`、`exam_weight`、`prerequisites`。
2. 检查 `knowledge/<subject>/tutorials/<knowledge_id>.md`：
   - **不存在** → 按模板新建（`source: agent` 或经管理台 LLM）。
   - **已存在且内容仍适用** → 打开引用；若本次讲解/追问补充了新例子/新易错点 → 执行「修订」。
   - **已存在但与本次精讲/批改/澄清结论冲突** → 执行「修订（纠正）」，不得并存矛盾说法。
3. **关联整合**（满足任一即做）：
   - 本次同时讲解了 `prerequisites` 或同卷多个 `knowledge_id`
   - 新建了相邻点教程
   - 批改或追问归因到多个 id  
   动作：在各方教程中更新 `related_ids`，并在正文增加或改写 `## 关联知识点`；需要时把对照例补进「例题演示 / 易错点」。
4. 写入后提醒学生在管理台「学习 / 知识点」刷新浏览；需要时「从仓库同步」。
5. 对话精讲：以**最新教程**做摘要，再立刻练习。

## 修订方式

| 场景 | 做法 |
|------|------|
| 小补充（多一例、多一条易错） | 直接改对应小节，`version += 1` |
| 纠正错误结论 | 改掉错误句，必要时在易错点写「曾易混成…」 |
| 整合关联点 | 更新 `related_ids` + `## 关联知识点`；双方教程都要改 |
| 追问澄清（高/中重要性） | 答完后立刻补进对应小节，`revision_note` 标注追问补充 |
| 管理台 | `POST /api/tutorials/{id}/revise`（`patch` / `integrate` / `correct`） |

可用管理台或 Agent 直接改 Markdown；Agent 改完应保证五段标题仍在。

## 教程文件约定

路径：`knowledge/<subject>/tutorials/<knowledge_id>.md`

文首 YAML 含：`knowledge_id`、`subject`、`title`、`target_level`、`version`、`source`、`updated_at`、`related_ids`、`revision_note`。

正文必须含：`## 一句话记住`、`## 核心概念`、`## 例题演示`、`## 易错点`、`## 自测提示`；可选 `## 关联知识点`、`## 自测参考`。

## 内容要求

- 面向初三、简体中文；暑假预习可略降起点。
- 禁止空话；修订时写清「补了什么 / 改了什么」。
- 关联整合要具体（对照、先后、易混），禁止只贴 id 列表。

## 与练习闭环

修订或整合后：若该点仍薄弱，引导短测或管理台「练习」；错题归因后优先修订「易错点」再让学生订正。
